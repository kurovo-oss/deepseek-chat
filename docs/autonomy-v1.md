# 受控自主 v1：目标、判断与行动

> 目标不是“造出意识”，而是让她有持久的意图、可解释的判断和受控的行动。
> 当前阶段只做“提议”，不自动执行外部动作。

## 阶段表

| 阶段 | 内容 | 默认 | 状态 |
|---|---|---|---|
| 1 | `goals` / `goal_actions` / `outcomes` 表；候选目标；计划页 | 只建议，不行动 | 已完成 |
| 2 | 低风险主动消息：复用 proactive 闸门，默认需确认 | 关闭自动发送 | 已完成（需手动确认） |
| 3 | 偏好周复盘：把 feedback/偏好卡提炼成“相处方式” | 只读建议 | 已完成（需手动采用） |
| 4 | 工具白名单：笔记/提醒；外部动作仍关闭 | 白名单 | 部分完成（笔记；提醒禁用） |
| 5.1 | 目标层级、进度、父目标 | 兼容旧目标 | 已完成 |
| 5.2 | 回复/反馈结果记录与进度 | 弱信号，不猜情绪 | 已完成 |
| 5.3 | 到期目标进入待确认队列 | 默认关闭 | 已完成（需手动开启） |
| 5.4 | 自主等级 / 每日动作上限 | 默认 confirm | 已完成 |
| 5.5 | 目标摘要进入对话上下文 | 只带进行中目标 | 已完成 |

## 数据

- `goals`：目标、原因、证据、优先级、状态、来源。
- `goal_actions`：后续阶段的可执行动作；阶段 1 只建表，不产生动作。
- `outcomes`：动作结果，后续阶段用于调整。
- 记忆继续用 `cards` / `feedback` / `growth`，不另造一套记忆。

## 阶段 1：只建议

- 目标只能来自已确认的 `cards` 或最近对话；
- 必须带 evidence，引用真实卡片编号；
- 一次最多 2 个候选；
- 只能新建候选目标，不能自己激活、删除或执行；
- WebUI「计划」页可以确认、暂停、完成、删除；
- “让她想一次”是手动入口；自动复盘由 `GOALS_ENABLED` 控制，默认关闭。

## 阶段 2：需要确认的主动

- 在计划页把候选目标“确认”为进行中；
- 点“准备主动”才会调用模型生成一句话，存成 `waiting_approval`；
- 点“确认发送”才走 `ProactiveScheduler.send_approved`，仍然受时段、额度、间隔、免打扰和 `Runtime` 暂停约束；
- 失败时动作保持待确认并显示原因，不会静默重试。

## 阶段 3：相处方式

- 记忆页「整理相处方式」读取 feedback 和已确认偏好；
- 只生成最多 3 条建议，显示在记忆页，不自动生效；
- 点「采用」才落成一张已确认的偏好卡，点「忽略」只关闭建议；
- 自动周复盘由 `STYLE_REVIEW_ENABLED` 控制，默认关闭。

## 阶段 4：工具白名单

- 已开放 `save_note`：只写本地 `notes` 表，不发 QQ、不进上下文；
- `send_message` 仍需确认，并走主动消息闸门；
- `schedule_checkin` 保持禁用，等提醒功能单独验收；
- 外部平台（空间/抖音/任何写操作）不在白名单内。

## 阶段 5：目标闭环

- `goals` 增加 `parent_id`、`progress`、`autonomy`、`last_outcome_at`；旧库自动补列；
- 他回复最近一次目标主动 → 记 `replied`，目标进度 +0.1；同一条动作只记一次；
- 他给「合拍 / 不准确」→ 对最近 6 小时内的目标主动记 `feedback_good/bad`，进度 ±0.1；
- 到期目标由 `AUTONOMY_ENABLED` 开启的调度器放进 `waiting_approval`，不发送；
- 计划页显示父目标、进度、自主等级和计划时间；
- 进行中的目标会以「你现在在做的事」进入上下文，最多 4 条 / 260 字。

```dotenv
AUTONOMY_ENABLED=false
AUTONOMY_MODE=confirm
AUTONOMY_MAX_ACTIONS_PER_DAY=1
```

## 安全边界

- 不伪造线下生活；目标只能是聊天内能完成的事；
- 不用愧疚/离开等话术驱动互动；
- 不自动改人格、不自动删记忆；
- 所有后续行动必须经过 `Runtime` 暂停开关、频率限制和审计。

## 配置

```dotenv
GOALS_ENABLED=false
GOALS_REVIEW_HOURS=20
GOALS_MAX_CANDIDATES=2
```
