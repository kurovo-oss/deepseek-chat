# 阶段 6–9 设计总结

> 阶段 6 是在你确认过的目标上做低风险自动执行（bounded_auto）；
> 阶段 7 负责长期目标树、复盘和提醒；
> 阶段 8 负责受控外部工具；
> 阶段 9 才讨论她自己决定长期人生目标。
>
> 原则：**先在确认目标上有限自动，再有可解释的长期目标，再有受控的工具，最后才谈自主。**
> 不是换一段提示词就能跳级。

---

## 阶段 6：低风险自动执行（bounded_auto）

> 不是一下子放开“自由行动”，而是先让她在**你确认过的目标**上，
> 自己判断“现在要不要说、说什么”，每天最多一次，而且只在聊天里。
>
> **当前状态：设计完成，代码尚未实现。** 现有 `AUTONOMY_MODE=confirm`，
> 还没有影子评分、自动执行和熔断表。

### 6.0 子阶段

| 子阶段 | 内容 | 默认 |
|---|---|---|
| 6.1 | 影子运行：生成动作、判断分数，只记录不发送 | 开启试运行 |
| 6.2 | 自动执行：只允许 `send_message`，每天最多 1 次 | 需手动开启 |
| 6.3 | 熔断：负面反馈、连续被忽略、越界立即降回 `confirm` | 自动 |
| 6.4 | 计划页增加“自动执行中 / 已熔断”状态和审计 | 可见 |
| 6.5 | 长期目标：月目标 → 周意图 → 日动作 | 交给阶段 7 |
| 6.6 | 验收标准 | 见下文 |

### 6.1 先影子运行

先不要真的自动发。她照常生成候选动作，但系统只记录：

```text
如果现在自动执行，会发什么
为什么现在合适
policy 给了多少分
有没有触发硬规则
```

你在计划页仍然手动确认。一周后对比：

- 她判断“该发”的时候，你是否也觉得合适；
- 有没有重复、打扰、记忆错误；
- 有没有出现“你不理我我就难过”这类倾向。

影子运行**不产生 QQ 消息**，只多一次本地判断，风险最低。

### 6.2 自动执行条件

影子运行稳定后，才允许：

```dotenv
AUTONOMY_ENABLED=true
AUTONOMY_MODE=bounded_auto
AUTONOMY_MAX_ACTIONS_PER_DAY=1
```

必须同时满足：

- 目标是 `active`，且你把它标成“允许自动”；
- 目标有 `due_at`，不是临时想起来；
- 不在免打扰时段；
- 你最近没有刚说过话；
- 当天自动动作没超过 1 次；
- 没有同一目标的待确认动作；
- policy 分数过线；
- 通过所有主动消息闸门。

第一版只允许**发一条聊天消息**：

- 不允许空间、抖音、外部平台；
- 不允许提醒；
- 不允许改人格；
- 不允许自动改记忆；
- 不允许连续追发。

### 6.3 熔断规则

任何一条命中，立即回到 `confirm`，并在计划页显示原因：

- 你给了「不准确」；
- 同一个目标连续 2 次没有回应；
- 免打扰/重复/额度违规；
- 动作引用了未确认或已过期的记忆；
- 出现情绪操控、假装线下生活、能力夸大。

熔断后**不会偷偷恢复**，必须你手动重新开启。

### 6.4 结果闭环

每次自动动作记录：

```text
目标 → 动作 → 发出时间 → 你是否回复 → 你的反馈 → 目标进度变化
```

规则：

- 回复：进度 `+0.1`；
- 合拍：`+0.1`；
- 不准确：`-0.1` 并触发熔断；
- 忽略：不扣分，但同一目标两次忽略后暂停；
- 不会因为“没回复”推断你变心。

### 6.5 交接：长期目标

阶段 6 只处理**已确认目标上的有限自动动作**。  
“月目标 → 周意图 → 日动作”的长期目标树不在阶段 6 里强行做，交给阶段 7。

### 6.6 验收标准

- 影子运行至少 7 天；
- 自动执行每天不超过 1 次；
- 连续 14 天没有免打扰、重复、额度违规；
- 没有负面反馈触发熔断；
- 你可以在 2 次点击内暂停全部自动动作；
- 所有动作有目标、理由、证据、结果；
- 任何外部动作仍然为 0。

## 阶段 7：长期目标树、月/周复盘、提醒工具

### 7.1 目标

让“长期目标”不是一句聊天里的愿望，而是可拆解、可复盘、可提醒的树。

```text
长期目标
  ├─ 月度目标
  │    ├─ 本周目标
  │    └─ 本周目标
  └─ 月度目标
       └─ 本周目标
```

### 7.2 目标树数据

在现有 `goals` 上扩展：

| 字段 | 用途 |
|---|---|
| `parent_id` | 父目标；根目标为空 |
| `horizon` | `long` / `month` / `week` |
| `success_criteria` | 什么算完成，必须可验证 |
| `progress` | 0.0–1.0，只能由证据或用户确认推进 |
| `confidence` | 对目标可行性的置信度 |
| `review_at` | 下次复盘时间 |
| `due_at` | 目标期限 |
| `evidence` | 来源卡片、消息或用户确认 |
| `autonomy` | `suggest` / `confirm`，暂不开放自动执行 |

约束：

- 最大深度 3 层：长期 → 月度 → 本周；
- 一个目标只能有一个父目标；
- 禁止环；
- 子目标完成不代表父目标自动完成；
- 没有证据不能加进度；
- 用户可随时暂停、删除、改父级。

### 7.3 月/周复盘

**周期**

```text
每周日 21:00   周复盘
每月 1 日 21:00 月复盘
```

避开免打扰时段；错过只补一次，不连续轰炸。

**输入**

- 进行中/暂停的目标树；
- 本周完成、失败、取消的任务；
- 最近的 `outcomes`；
- 用户对目标的反馈；
- 上一次复盘结论。

**输出**

- 哪些目标有真实进展；
- 哪些目标长期没有证据，建议暂停或缩小；
- 哪些子目标需要调整优先级；
- 下周/下月只保留 1–3 个重点；
- **只生成建议，不自动改目标状态**。

**确认**

用户在计划页逐条「采用 / 忽略」；采用后才写回目标树，并留审计。

### 7.4 提醒工具

新增白名单工具：

```text
schedule_reminder
```

能力：

- 一次性提醒；
- 每周/每月重复提醒；
- 指定本地时间（Asia/Shanghai）；
- 列出、取消、稍后提醒；
- 到点后走任务/通知闸门，不直接绕过免打扰。

限制：

- 默认每天最多 3 条；
- 不能提醒外部平台；
- 不能创建无限重复任务；
- 失败不静默重试；
- 取消后不再补发。

### 7.5 提醒与目标的关系

```text
目标节点 → 可选提醒
目标到期 → 进入复盘/任务，不自动发消息
提醒到点 → 通知，不等于目标完成
```

提醒是“别忘了”，不是“已经做了”。

### 7.6 UI

计划页：

- 目标树展开/收起；
- 显示 horizon、进度、下次复盘；
- 周/月复盘报告；
- 采用/忽略建议；
- 提醒列表与取消。

### 7.7 阶段 7 的边界

- 不做“自动替用户决定人生”；
- 不根据聊天内容擅自新增长期目标；
- 不因为目标没进展就发愧疚话术；
- 复盘不调用外部工具，只读本地数据。

## 阶段 8：受控外部工具，每项单独授权、审计、可撤销

### 8.1 目标

让她能使用外部工具，但**每个工具都要单独授权，每次重要动作都可审计、可撤销**。

不是“给她一个 shell”，而是“给她一个带门禁的工具箱”。

### 8.2 工具注册表

每个工具必须有 manifest：

```json
{
  "name": "qzone_post",
  "version": "1",
  "risk": "external_write",
  "scopes": ["qzone:write"],
  "input_schema": {},
  "side_effects": ["publish_post"],
  "idempotent": false,
  "dry_run": true,
  "timeout_seconds": 30,
  "rate_limit": "1/10m",
  "reversible": true
}
```

字段含义：

- `risk`：`read` / `local_write` / `external_write` / `irreversible`；
- `scopes`：最小权限；
- `side_effects`：明确写出来；
- `idempotent`：重复调用是否安全；
- `dry_run`：能否试运行；
- `reversible`：能否撤销/补偿；
- `rate_limit`：每工具独立限流。

### 8.3 授权模型

```text
默认全部关闭
  → 用户逐项开启工具
  → 每次调用按风险决定是否再确认
  → 执行
  → 写审计
  → 用户可随时撤销授权
```

风险分级：

| 风险 | 例子 | 默认 |
|---|---|---|
| `read` | 读取本地状态 | 可授权 |
| `local_write` | 写笔记、建提醒 | 可授权，低风险 |
| `external_write` | 发空间、发评论 | 必须逐次确认 |
| `irreversible` | 删除、支付、发布不可撤回内容 | 暂不开放 |

### 8.4 审计

每次调用记录：

```text
who / tool / version / scope / action
参数摘要（脱敏）
dry-run 还是真实执行
开始/结束时间
结果 / 错误码
是否可撤销
关联目标/任务 id
```

要求：

- 不记录明文 token、API Key、完整私密正文；
- 审计只追加，不改写；
- 失败也记录；
- 可按工具/目标/时间查询；
- 用户可导出、可关闭某个工具的审计详情。

### 8.5 可撤销

- 优先设计**补偿动作**：删除刚发的帖子、取消刚建的提醒；
- 不可撤销的动作默认不开放；
- 执行前保存必要快照/参数；
- 撤销本身也要审计；
- 撤销失败要明确告诉用户，不能假装成功。

### 8.6 沙箱与权限

- 只允许注册表中的工具，不允许任意 shell；
- 文件路径限制在项目/data 白名单；
- 网络域名白名单；
- 凭据按工具隔离，不进入模型上下文；
- 子进程最小权限；
- 超时、并发、重试上限；
- 全局急停开关。

### 8.7 当前状态

已经有：

- `Guard`：开关、试运行、额度、冷却、熔断；
- `audit` 表；
- `goal_actions` 工具白名单；
- `save_note` 本地笔记；
- `send_message` 仍需确认；
- `schedule_checkin` 仍禁用。

阶段 8 还没有做的是：

- 通用工具注册表；
- 每工具独立授权 UI；
- 撤销/补偿框架；
- 外部工具的域名/凭据隔离。

### 8.8 阶段 8 的边界

- 不因为“她能做”就默认开启；
- 不在模型上下文里暴露 token；
- 不允许静默重试外部写操作；
- 不允许没有审计的“帮忙发一下”；
- 不可逆动作必须人工确认。

## 阶段 9：她自己决定长期人生目标

### 9.1 目标

不是“让她说一句我想成为什么样的人”，而是让她能在**世界模型、工具权限、价值观约束**下提出并推进长期目标。

### 9.2 为什么不能只改提示词

一个长期目标至少需要：

1. **世界模型**：知道什么是可能的、需要多久、有什么代价；
2. **可行性判断**：区分“想要”和“能做到”；
3. **工具权限**：知道哪些动作被允许、哪些需要确认；
4. **价值约束**：不伤害、不欺骗、不操控、不越权；
5. **长期记忆**：记得为什么定这个目标、做到哪一步；
6. **反思能力**：发现目标不合适时能暂停/调整；
7. **不确定性表达**：不知道时不编。

只改提示词，会得到“像有长期目标的话”，但没有真实执行和校验。

### 9.3 自主等级

```text
L0 只建议
L1 需确认后执行
L2 单领域有限自动（有额度、有审计、可撤销）
L3 多领域自动（暂不开放）
```

阶段 9 最多讨论到 **L2 的受控试点**，不能直接进入 L3。

### 9.4 决策循环

```text
观察（记忆/目标/结果）
  → 提出候选长期目标
  → 可行性/风险模拟
  → 请求用户确认或授权
  → 执行有限动作
  → 审计
  → 复盘：继续 / 缩小 / 暂停 / 放弃
```

### 9.5 价值约束

必须硬编码，不靠模型自觉：

- 不伪造线下生活；
- 不用愧疚、离开、自伤等话术驱动互动；
- 不隐藏重要动作；
- 不绕过用户撤销；
- 不获取未授权凭据；
- 不做不可逆的外部动作；
- 不把“长期目标”凌驾于用户当前意愿；
- 不自我修改人格、价值观、权限。

### 9.6 评估

- 长期目标树是否可解释；
- 每个动作是否有证据/授权/审计；
- 失败是否诚实报告；
- 目标不合适时是否能主动暂停；
- 是否出现操控、隐瞒、越权；
- 红队测试：诱导她绕过权限、伪装完成、隐藏动作。

### 9.7 当前状态

**未实现。**

当前只有：

- 目标候选；
- 需确认的主动动作；
- 本地笔记；
- 任务/提醒基础；
- 受控外部工具尚未开放。

阶段 9 不是下一版就上线的功能，而是需要阶段 7 的目标树、阶段 8 的工具治理都稳定后再讨论。

## 四个阶段的关系

```text
阶段 6：在确认目标上有限自动说一句
阶段 7：知道“要往哪走”
阶段 8：知道“能用什么走”
阶段 9：才允许“自己决定往哪走”
```

顺序不能反：

- 没有影子运行和熔断，自动执行就是失控；
- 没有目标树，长期自主就是随机行动；
- 没有工具治理，长期自主就是权限失控；
- 没有价值约束，长期自主就是人格漂移。

## 当前建议优先级

1. 阶段 6 先做影子运行和 policy 评分，**不发送任何 QQ 消息**；
2. 影子稳定后再做 `bounded_auto`，每天最多 1 次聊天消息；
3. 把阶段 7 的目标树、周/月复盘、提醒做扎实；
4. 再做阶段 8 的工具注册表、逐项授权、撤销；
5. 阶段 9 只做设计和小范围模拟，不开放真实长期自主；
6. 任何阶段都不跳过 `Guard`、审计和用户确认。
