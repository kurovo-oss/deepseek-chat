## 3. P0：需要先修

### P0-1 空间连续 16 次失败，而且失败原因被吞了

- 最后成功：11-05 21:10（id 8，牛腩）。之后 11-06 8 条、11-07 8 条，全部 `failed`，错误字段只有"接口失败"。
- 失败记录里 `images=[]`，说明不是配图上传导致的；每 30 分钟重试一次，正好是熔断后的冷却节奏。
- `publish()` 只在 `data["message"]/["wording"]` 有值时才记错误，HTTP 超时/解析失败会返回 `(False, {})`，于是统一变成"接口失败"——**原始返回、HTTP 状态、耗时全丢了**，现在无法定位。
- 附带两个坑：
  - 成功时 `tid = data.get("tid")`，但 OneBot 返回是 `{"status":"ok","data":{"tid":...}}`，所以 3 条成功记录的 `tid` 全空，想删都删不了。
  - 超时属于"结果未知"，现在当失败继续重试；如果第一次其实发成功了，会重复发说说。
- 建议：给 `send_qzone_msg` 单独 60s 超时；失败时把 HTTP 码、原始 body、耗时写进 `qzone_posts.error`；成功从 `data.data.tid` 取 tid；结果未知时不自动重试，转为草稿等你确认；补 `delete_qzone_msg`。

### P0-2 没聊天 → 生活线/摘要断料 → 说说复读

- 生活线只在 `handle_message` 里触发（`engine.py:167`），11-07 你一条没发，所以 `data/life/2026-11-07.md` 不存在。
- 11-07 空间仍然每半小时写一条，只能拿 11-06 的摘要和旧生活线凑；8 条开头清一色：

  - "早上眼睛都没睁开…跟他说了句想他"
  - "今早醒来第一个念头就是他…"
  这正是 11-06 日摘要的内容（摘要里就写着"她跟他说睡醒第一件事就是想他…他只提到要上班"）。
- 建议：生活线改成每天 09:00 定时生成（没有聊天也生成"今天没干嘛"的平淡日子）；空间 prompt 只允许用今天/昨天的摘要，没料就写短句，不许拿旧摘要扩写；同一摘要连续使用时直接跳过当天发布。

### P0-3 事实记忆是空转

- `facts=0`、`fact_events=0`；`facts:last` 停在 11-06 20:38，说明 `extract()` 只完整跑过一次，然后一条没写。
- 代码里证据校验很硬：模型给的 `quote` 必须能在你最近 24h 的消息里找到**完全子串**，找不到就丢；模型通常会把你的话改写，于是整批被丢，且只 `log.debug`，日志里看不到。
- 结果是 `/记忆` 里"事实 0 条"，和 `MEMORY_FACTS_ENABLED=true` 的预期不符。
- 建议：证据校验改成"归一化后子串或相似度 ≥0.8"；丢弃时记 `info`（带 quote 和原因）；`/记忆` 增加"上次抽取：时间/丢弃数"；先用 11-06 的 29 条消息做一次离线回放验证。

### P0-4 忙闲会吞掉直接问候，补回故事还对不上

- 11-08 11:47:07 你说"早上好" → 日志"她这会儿在拼拼图，这条先不回（忙完补）"；11:47:36 你问"怎么不说话"，11:47:40 才回。
- 回复是"刚在叠衣服呢"，和 presence 的"拼拼图"不是同一件事——补回时的 presence 注入没有钉住当时的状态。
- 你主动开口、还是问候，被静默处理，体验上就是"已读不回"。
- 建议：问候/疑问句/带"在吗"的消息不参与 busy 跳过；真要忙，发一句"在忙，晚点回"而不是静默；补回 prompt 里固定写入"你刚才在拼拼图"，别让它自由发挥。

### P0-5 编造的生活被当场质疑

- 11-06 14:21–14:22：她说"我房间在重新收拾，地上摊着三只纸箱"；你问"你哪里来的房间"；她回"唔…我这会儿脑子有点转不过来"，再补一个表情包和语音。
- 这是人设层的问题：她设定里没有"房间/纸箱"这些实体，生活线却会生成具体家居细节；一旦你追问，她只能装傻。
- 建议：生活线只允许写"可被设定容纳"的场景（房间可以有，但要先写进设定卡并保持一致：住哪、和谁、房间什么样）；或者明确"她住在你附近的小单间"，把房间变成稳定设定，而不是每次临时编。短期至少在她被追问时给一句一致的圆场，而不是"脑子转不过来"。
