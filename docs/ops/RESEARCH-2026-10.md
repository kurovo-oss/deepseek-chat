# 同类项目调研（2026-10）

> 范围：GitHub 上"DeepSeek / LLM 接入 QQ"的开源项目、各家文档、B 站与教程站。
> 目的：看别人把哪些事做成了"标配"，对照本项目的缺口，排出优先级。
> 结论先行：**我的记忆层做得比多数同类细，但三个基础件缺失——视觉输入、风格隔离、协议端自愈。**

## 一、生态地图

| 项目 | 定位 | 值得看的点 |
|---|---|---|
| [MaiBot（麦麦）](https://github.com/Windpicker-owo/MaiBot) | 群聊"赛博网友"智能体 | 表达学习（学群友说话风格）、动态人格、基于图的持久记忆、实时思维、聊天时机控制 |
| [AstrBot](https://github.com/Chenlong-Tao/AstrBot) | 多平台 LLM 机器人框架 | 多模态（图片理解、Whisper 语音转写）、插件系统、WebUI、Agent 工具、Dify 接入 |
| [LangBot](https://github.com/RockChinQ/LangBot) | 生产级多平台机器人 | RAG 知识库、MCP、多流水线、WebUI、限流与敏感词 |
| [dsh-napcat](https://github.com/wzwei1990/dsh-napcat) | DSH 的 NapCat 通道插件 | 群记忆三层、表情包目录+检索、伪人模式（泊松插话、`__SKIP__` 闭嘴）、收图/文件、会话自愈 |
| [dsh-im-qq](https://github.com/988hj7tczd-oss/dsh-im-qq) | QQ 官方机器人通道 | WS 长连接与 RESUME、会话隔离、审批桥、白名单 fail-closed |
| [NapCat](https://github.com/NapNeko/NapCatQQ) | 协议端（本项目底层） | 本项目所有"掉线"都发生在这层 |

B 站/抖音侧的内容基本是"3 分钟接入"教程（AstrBot+NapCat+Docker 这一类），
例如 [AstrBot+NapCat 部署教程](https://www.cpolar.com/blog/5-minute-deployment-of-astrbotnapcat-connect-deepseekai-to-your-qq-with-docker)、
[MaiBot 演示视频](https://www.bilibili.com/video/BV1amAneGE3P)。没有独占的新机制可抄，
价值集中在上面几个仓库的 README 里。

## 二、他们共同做对的五件事

1. **记忆分三层**：热（最近 N 条原文）/ 温（滚动摘要 + 人物像 + 偏好 + 待办）/
   长期（事实、黑话、关系）。本项目有热（窗口）和长期（卡片），温层是**日摘要**，
   结构对得上。
2. **人格 = 内核 + 可演化层**，不是一段静态文案（MaiBot 的"动态人格"）。
3. **表达风格单独建模**（MaiBot 从群聊里学说话方式），而不是塞在人格描述里。
4. **多模态是标配**：图片理解、语音转写。只有本项目还停在"我看不到图片"。
5. **运维层是产品的一部分**：WebUI、断线重连、启动器、插件市场、内容审核。

## 三、本项目的对照

| 能力 | 本项目 | 同类 |
|---|---|---|
| 长期记忆（卡片/权重/注入） | ✅ 三重权重 + 命中次数 + 钉住 | ✅ 多为向量库或图存储 |
| 原话召回 | ✅ FTS5 trigram + 有界 LIKE 兜底 | ✅ 多为 embedding |
| 记忆整理 | ✅ 做梦重写记忆本 + 日摘要 | ✅ 滚动摘要 |
| 待确认事实 / 隔天自动转正 | ✅ **未在同类里见到等价实现** | — |
| 情绪与驱力 | ✅ 三驱力 + 词表共情 | 部分有（MaiBot 情绪系统） |
| 主动消息 | ✅ 闸门（时间/频率/沉默） | ✅ 泊松插话 + `__SKIP__` |
| 表情包 | ⚠️ 只有 14 个 tag，模型不知道库里有什么 | ✅ 目录注入 + 检索工具 |
| 看图 | ❌ 只能读文字 | ✅ 视觉模型 |
| 语音 | ❌ | ✅ ASR/TTS |
| 风格演化 | ❌ 静态 prompt | ✅ 动态人格 / 表达学习 |
| 协议端自愈 | ❌ 掉线只能手工重启 | ✅ 自动重连/自愈 |
| 管理界面 | ❌ 只有 `/status` 与日志 | ✅ WebUI |
| 模型容错 | ❌ 单模型，401 直接兜底 | ✅ 多模型可切换 |
| 测试 | ✅ 481 个用例 | 少见同等规模 |

## 四、问题清单（按优先级）

### P0 — 影响"能不能用"

1. **风格污染没有机制保障**。改完人格，实测在无历史环境很好、接进机器人立刻退回旧模板
   （上下文里 20 条旧回复的权重高于系统提示）。目前靠手工 `/reset`，
   应该做成**人格纪元**：换 prompt 时记一个时间戳，早于它的 assistant 消息不进上下文。
2. **看不见图**。用户发表情包、照片，她只能说"看不到"（记忆卡 #2 就是这么来的）。
   需要接一个视觉模型（deepseek 系无视觉），做模型路由：有图走 VL，无图走主模型。
3. **协议端无自愈**。一天掉三次，其中一次凭证失效要重扫码；看门狗只告警不处理。
   应做：探测 3001 → 自动结束 QQ/NapCat → 重启 launcher → 抓二维码 → 通知。

### P1 — 影响"好不好用"

4. **表情包不透明**。模型只拿到 tag 列表，选图基本靠猜。抄目录注入：每轮带
   「【可用表情】happy(12)：…（每类 2 个示例）」，长文生成一次后缓存。
5. **人格不进化**。建议只做"关系层"（最近几周的相处基调、你们之间的梗、他在意的事），
   落 `data/persona_state.md`，做梦时更新，注入带字数预算。
   **不要**照抄"表达学习"：那是从群里多人语料学，单人私聊里学出来的会是"复读他的语气"。
6. **没有可观测界面**。巡检全靠手工看日志；至少做一个只读状态页（本地 HTTP）。

### P2 — 锦上添花

7. 模型 fallback（主模型失败换备选，而不是直接兜底话术）。
8. 语音（先把 ASR 做了，比 TTS 有用）。
9. 内容审核（自己用不需要；如果要分享给别人，必须加）。
10. 插件化（零依赖单体是取舍，不是缺陷；加功能要改代码可以接受）。

## 五、个人服务版方案（2026-10-30 修订）

> 前提：只部署给一个人用（本机、单 QQ 号、私聊、无人值守）。按这个前提重新裁剪。

### 砍掉（不做的）

| 项 | 为什么砍 |
|---|---|
| 内容审核、敏感词过滤、限流 | 不会有人恶意使用；自己跟自己较劲没意义 |
| 多平台（Telegram/微信/飞书） | 只上 QQ |
| 群聊、多用户隔离、会话路由 | 只服务一个人，一个 session |
| WebUI 管理面板、多流水线、插件市场 | 单人维护，改成"每天一条运行日报"更省事 |
| RAG 知识库、Dify 接入、计费配额 | 用不上 |

### 加强（单人部署真正的风险）

按事故概率排序。**2026-10-30 早上**就撞了第 1 条：电脑 9:21 重启，
开机自启的机器人读到**用户级环境变量里的旧 API key**（覆盖了 `.env`），
整个上午在发兜底话术；NapCat 也因重启未登录。最贵的事故不是模型答不好，
是"没人看着就烂在那儿"。

1. **重启后自愈**（P0）
   - 单一配置来源：删掉用户级 `MODEL_API_KEY`，只认 `.env`（已做）
   - 启动自检：模型 key 探测失败 → 立刻告警（不能只写日志）
   - NapCat 未登录 → 自动抓二维码到固定路径 + 桌面提示，而不是等人发现
   - 进程钉住：退出后自动拉起（现在 `exit /b` 就没了）
2. **数据不丢**（P0，比任何界面都重要）
   - WAL 模式下直接拷 `.db` 会丢数据，必须 `VACUUM INTO` + 打包 `data/`
   - 每天一次快照，保留 7 天；给一条恢复命令
3. **风格隔离**（P0）：人格纪元，旧 assistant 消息不进上下文，不用手工 `/reset`
4. **看得见图**（P0）：单人场景体验提升最大的一项；需要接一个带视觉的模型做路由
5. **每天一条运行日报**（替代 WebUI）：消息数、token 花费、异常次数、备份状态，
   直接发到 QQ——本来就是我每天都会看的东西

### 推迟 / 不做

- 表情包目录注入：等图库攒到几百张再说（现在 14 个 tag 够用）
- 关系层演化（人格进化）：有价值，但排在"不挂、不丢"之后
- 语音、插件化、多平台：不做

### 一周排期

| 天 | 做什么 |
|---|---|
| 第 1 天 | 配置单一来源（已做）+ 启动自检告警 + NapCat 未登录检测 + 自动拉起 + 备份脚本 |
| 第 2 天 | 风格隔离（人格纪元） |
| 第 3–4 天 | 视觉接入（VL 模型路由） |
| 第 5–7 天 | 运行日报 + 关系层演化（可选） |
